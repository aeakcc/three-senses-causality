### 11a. E3: кросс-фит на полностью размеченных аннотациях CRED (зафиксировано 23.09.2026 до постановки задач E3)

**Раскрытие.** Код (`--init-from`, aux-голова `pc`, `cred_split.py cv`, `embed.py`, `ops/make_queue_p2.py`) и CPU-смоук на крошечной модели сделаны до коммита. Метки всех 266 аннотаций CRED уже читались (статья AIBH §8–§10, в том числе тест). Тест CRED израсходован 18.09; здесь он — лишь часть пула кросс-фита, поэтому E3 — новый эксперимент со своим протоколом, а не повторное открытие теста. Ни одна рука E3 ещё не обучалась и не оценивалась.

1. **Пул и фолды.** Оценочный пул — 159 аннотаций (111 train + 17 val + 31 test), то есть все, кроме 107 аннотаций train, где размечены только каузальные пары (правило `cred_pooled_fix.py`; две тестовые аннотации со сплошь каузальными парами размечены полностью и остаются). 5 фолдов `StratifiedGroupKFold(5, shuffle, random_state=0)` по PMID со стратой «есть каузальная пара»; файлы `data/CRED/cv/` (manifest sha256 41ec5026…2f3c). 107 позитив-только аннотаций всегда в обучении и никогда в тесте фолда; их неразмеченные пары не бывают негативами. Строки оценки — `cred_s10.load_rows` по всем сплитам, ограниченные пулом (strict: недостижимая пара получает скор 0).
2. **Руки** (каждая даёт OOF-скор каждой строки; ансамбль = среднее вероятностей сидов 42–44):
   - **Z** — zero-shot bc8all (ансамбль `re_bl_base_bc8all` s42–44, уже посчитанный `ens_bc8all/pred_cred.jsonl`), скор p(Pos)+p(Neg). Не обучается.
   - **C** — совпадение в одном предложении (флаг авторов CRED), без модели.
   - **S** — стекер по спецификации §10b (те же признаки и выбор C), переподгоняемый на обучающих фолдах (только полностью размеченные достижимые пары).
   - **PL** — линейная проба на замороженном представлении пары bc8all: вход головы [e_disease; e_gene; c] (2304) из `embed.py --run` для каждого сида; StandardScaler + логистическая регрессия L2, C ∈ {1e-4, 1e-3, 1e-2, 1e-1, 1} по AUPRC на внутреннем GroupKFold(4) по PMID обучающих фолдов (при равенстве меньший C); обучающие строки — достижимые размеченные одно-генные пары обучающих фолдов плюс каузальные пары позитив-только аннотаций; вероятности трёх сидов усредняются.
   - **P0** — та же проба на представлении сырого BioLinkBERT-base (`embed.py --backbone --seed s`, s = 42–44; маркеры инициализируются сидом).
   - **FL** — дообучение бинарной головы `pc` от чекпоинта bc8all того же сида: `--init-from re_bl_base_bc8all_sS/best --train empty.json --joint cv/pc/cred.json --label-handling set --corpus-tag --aux-heads pc --aux-weight 1.0`, 12 эпох фиксированно (`--epochs 12 --stop-epoch 12`), lr 3e-5 / 1e-4, batch 4 × 2; фолд держится через `--heldout Test foldK.txt`. Скор — p_pc(1).
   - **F0** — то же от сырого BioLinkBERT-base (без `--init-from`).
   - **J** — рецепт A2 на фолде: BioRED Train + BC8-400 + `cv/set/cred.json` (без фолда), `--label-handling set --corpus-tag`, до 30 эпох, ранняя остановка по BioRED Dev; скор p(Pos)+p(Neg) под тегом `cred`.
   - **Q** — Qwen3-8B, условие T (§10c, уже посчитанные скоры строк подгонки и теста), описательно; на CRED не обучается.
   Команды — `ops/queue_p2/` (генератор `ops/make_queue_p2.py`), первым идёт смоук `p2e3_00_smoke` (1 эпоха); основные задачи ставятся только после его успеха.
3. **Метрики.** Первичная — AUPRC по объединённым OOF-скорам всех строк пула (strict), взвешенная документным бутстрэпом (10 000 ресэмплов, seed 0, `cred_eval.weighted_ap`). Вторичные: F1 при правиле порога руки (FL, F0: p_pc ≥ 0.5; J: ≥ 0.5; PL, P0, S: максимум F1 на внутренних OOF обучающих фолдов, при равенстве больший порог; Z, Q: максимум F1 на обучающих фолдах того же фолда); AUPRC и F1 по фолдам; внутри/между предложениями.
4. **Подтверждающее семейство E3** (Холм, m = 2, α = 0.05, парный документный бутстрэп):
   - **H_E3a:** AUPRC(PL) − AUPRC(Z) > 0 (одностороннее): пертурбационный смысл линейно извлекается из представления модели, обученной в смысле L, сверх её собственного L-скора.
   - **H_E3b:** AUPRC(FL) − AUPRC(F0) ≠ 0 (двустороннее, p = 2·min(доля ≤ 0, доля ≥ 0)): обучение в соглашении BioRED меняет усвоение пертурбационного смысла.
   Остальные разности (PL − P0, FL − PL, J − FL, S и C против всех, Q) — оценки с 95 % CI без проверки гипотез.
5. **Выбывание и перезапуски.** Упавшая задача перезапускается один раз той же командой; замена сида запрещена. Рука без полного набора 15 OOF-файлов к анализу получает p = 1 в своей гипотезе и описывается как выбывшая. Никакие гиперпараметры рук после появления их OOF-скоров не меняются.
6. **Описательно:** micro-F1 на BioRED Dev у FL (забывание соглашения BioRED), у J против bc8all.

### 11b. E1, E2, E4: смыслы на внешних кураторских данных и конструкциях (зафиксировано 23.09.2026 до первого скоринга этих наборов)

**Раскрытие.** Наборы собраны и проверены без моделей: сборщики `docs/results/paper2/build_{clingen,rgd,percha,biotriplex}.py`, `swap_build.py`, подмножества `e1_sets.py`. Известно до коммита: число единиц и покрытие по классам; ручная проверка 15 предложений на класс Percha (MUT 14/15, CAUSE 11, UP 11, DOWN 6, EXPR 10, ASSOC 7, MARKER 11, RISK 11, THERAPY 10; `docs/research/paper2/percha_constructions_sample.md`); симуляция ревьюера: при скоре единицы «максимум по кандидатным парам» случайные скоры дают AUROC 0.54–0.55 из-за разного числа кандидатов по классам — поэтому первичный анализ только на единицах ровно с одной кандидатной парой. После этого класс DOWN (ловит нокдаун и лекарства) убран из первичного контраста E4. Ни одна модель на ClinGen, RGD, Percha, BioTriplex и заменённых документах не запускалась. Отбор PMID: исключены все PMID BioRED, BC8 и CRED (проверено на файлах, 0 пересечений).

1. **Читатели (замороженные, без обучения).** L = ансамбль bc8all s42–44; P = ансамбль A2 (`a2_cred_bc8all` s42–44) под `--corpus cred`; Lp = тот же ансамбль A2 без тега корпуса (соглашение BioRED); L0 = ансамбль BioRED-only base s42–44 (только Percha, BioTriplex, CRED). Скор пары s = p(Pos) + p(Neg). **Внутримодельный контраст** d = logit s_P − logit s_Lp (клип [1e-6, 1−1e-6]): те же веса и текст, меняется только тег соглашения. Задачи — `ops/queue_p2/e1_*` (`ops/make_queue_p2_score.py`).
2. **Единицы и классы** (`units.candidate_pairs`; скор единицы = скор её единственной кандидатной пары):

Набор `data/paper2/e1/clingen_*` (5 456 единиц, 5 257 документов; sha256 units 37d73c2a…cb390c07… docs 6d1bc3d5…cbf319b6).
   - RGD (ручные аннотации человек, CC BY 4.0): единица (PMID, ген, набор MeSH), классы — коды доказательств; IEP и IAGP урезаны до 3 000 единиц каждый (random.Random(0)). Набор `data/paper2/e1/rgd_*` (8 238 единиц, 7 255 документов; units ac9b8177…74552733, docs adcfd8da…0be1d49b).
   - Percha & Altman 2018 (CC BY 4.0): 5 400 предложений Medline, 600 на класс конструкции по триггеру на пути зависимостей между сущностями (правила — `build_percha.py`); units 4fa6ac0a…f32d495e, docs 9c0aa149…9d947580.
   - BioTriplex (аннотации, 121 единица) — только описательно.
3. **Подтверждающее семейство E1/E4/E2** (Холм, m = 4, одностороннее, α = 0.05). Статистика — AUROC (ничьи = 0.5) величины d для класса A против класса B; единицы, попадающие в оба, исключаются; кластерный бутстрэп по PMID, 10 000 ресэмплов, `default_rng(0)`; p = доля ресэмплов с AUROC ≤ 0.5.
   - **H1 (ClinGen):** AUROC(d; GEN_CLV против EXP_A ∪ EXP_B ∪ EXP_U) > 0.5.
   - **H2 (RGD):** AUROC(d; IMP ∪ IGI против IEP) > 0.5.
   - **H3 (Percha):** AUROC(d; MUT ∪ CAUSE против UP) > 0.5.
   - **H4 (E2, текст, а не имя):** на документах, где ген заменён «неизвестным» символом (условие u; `data/paper2/e1/swap_clingen_u.json`, e0602e92…d11981b9), AUROC(d; GEN_CLV против EXP) > 0.5.
4. **Оценки с 95 % CI без проверки гипотез.**
   - Перекрёст по отдельным читателям (предсказание двойной диссоциации): AUROC_L(EXP против GEN_CLV) > 0.5 и AUROC_P(GEN_CLV против EXP) > 0.5 на ClinGen; AUROC_L(UP против MUT ∪ CAUSE) > 0.5 и AUROC_P(MUT ∪ CAUSE против UP) > 0.5 на Percha; на RGD — AUROC_P(IMP ∪ IGI против IEP), для L направление не предсказывается (соглашение BioRED даёт знак и нокауту).
   - Профили средних скоров по всем классам для каждого читателя (ClinGen, RGD, Percha, BioTriplex); контрасты MS_ORG ∪ MS_CELL ∪ RES против EXP (ClinGen), IAGP против IEP и NOT_IAGP против IAGP (RGD), DOWN, RISK, ASSOC, MARKER против UP (Percha); L0 на Percha.
   - Чувствительность: только человеческий Entrez (без id ортологов); только якорь `pair`.
   - E2: условие k (известный ген); средний Δlogit и ρ Спирмена между исходным и заменённым скором; страты «пара есть в GenCC D/S/M/Supportive» против «нет»; на CRED — ΔAUPRC для L и L0 (не обучались на CRED) и для рук E3 FL/F0/J на своих фолдах (скоринг заменённых документов фолда k моделями фолда k, задачи ставятся после E3).
   - Исследовательское: агрегирование P и L по PMID курирования и контраст Definitive против Refuted ∪ Disputed (ожидание «нет различия»: утверждение текста ≠ валидность).
5. **Правила.** Состав единиц, классы, читатели и статистики после появления скоров не меняются; упавшая задача перезапускается один раз той же командой. Все числа статьи — из `e1_eval.py` / `e2_eval.py`, пересчёт независимым кодом перед отправкой.

### 11c. E5: смысл V — голова типа клинического доказательства (зафиксировано 23.09.2026 до обучения и до любого скоринга тестов E5)

**Раскрытие.** Код и наборы (`docs/results/paper2/e5_sets.py`, `e5_eval.py`, `ops/make_queue_p2_e5.py`, 5-классовый `data.EV_CLASSES`) сделаны до коммита. Скоринг E1 (§11b) по единицам ClinGen, в том числе из будущего среза, делается замороженными читателями без обучения на ClinGen и в E5 не используется.

6. **Правила.** Гиперпараметры, эпохи и состав рук после появления их выходов не меняются; упавшая задача перезапускается один раз; TEST_2026 и RGD_EXT оцениваются одним прогоном `e5_eval.py` после того, как все девять ранов и шесть задач скоринга завершены.

### Уточнения и отклонения §11 (записано 23.09.2026, до появления выходов E1, E4, E5 и рук PL, P0, J)

*Уточнения* — реализационные детали, которых не было в тексте §11a–c; зафиксированы по отчёту независимого верификатора `docs/results/paper2/verify_p2.py` (написан по тексту предрегистрации без чтения основных оценщиков) до просмотра результатов:
1. Перекрёст отдельных читателей (§11b п. 4) считается по сырому скору s, не по logit с клипом.
2. Бутстрэп: основные оценщики используют одни и те же ресэмплы (`default_rng(0)`, 10 000) для всех систем одного набора; доверительные интервалы — 2.5 / 97.5 перцентили; точечная оценка — статистика на исходной выборке (бутстрэп только для CI и p). Верификатор берёт свой поток на каждую статистику; расхождение в пределах ошибки Монте-Карло допустимо.
3. «EXP» в H1 и H4 = EXP_A ∪ EXP_B ∪ EXP_U.
4. Единицы RGD, делящие одну кандидатную пару (9 пар, ни одна не IMP/IGI/IEP), не схлопываются.
5. Рука C (§11a) строгая: недостижимые строки получают 0 и при same_sent = 1.
6. Ансамбль по сидам усредняется по паре до максимума по кандидатам составного гена.
7. Правило «p = 1 без полного набора OOF» (§11a п. 5) применяется как «неполное покрытие строк пула».
8. TF-IDF: C выбирается по AUROC на объединённых OOF-прогнозах пяти фолдов (так посчитаны раскрытые 0.911 / 0.941 / 0.945); lbfgs, max_iter 2000.
9. Для RGD_EXT правило многометочных единиц и argmax для macro-F1 — те же, что для TEST_2026 (argmax по трём перенормированным классам).

*Отклонения:*
1. **TF-IDF и MAJORITY оценены на запечатанных TEST_2026 и RGD_EXT раньше срока.** При проверке верификатора на синтетических V-прогнозах его подкоманда `e5` обучила настоящие TF-IDF и MAJORITY и посчитала их на TEST_2026 и RGD_EXT (23.09.2026 ~23:30), хотя §11c п. 6 требует одного прогона после всех девяти ранов. Эти системы не требуют GPU и полностью заданы §11c (C = 10 выбран до коммита); ничего по этим числам не подбиралось, основной автор анализа их не просматривал до общего прогона. Файл с этими числами оставлен как есть (скретч сессии). `verify_p2.py e5` теперь отказывается работать, пока нет всех шести файлов прогнозов V.

### 11d. Поисковые анализы по рецензии Gemini (записано 24.09.2026 до их запуска; не подтверждающие, без поправки Холма)

Основание: `docs/research/paper2/gemini_review_2026-09-24.md` п. 1–2. Результаты §11a–c известны; эти анализы добавлены после них, поэтому в статье помечаются как поисковые (exploratory, post hoc).

1. **Две раздельные головы на одном замороженном энкодере (P\*).** Энкодер — bc8all s42–44 без изменений. Голова L — его собственная голова BioRED (читатель L §11b). Голова P\* — линейная проба §11a (PL: StandardScaler + L2-логистическая регрессия на входе головы [e_disease; e_gene; c], C ∈ {1e-4…1} по внутреннему GroupKFold(4) по PMID) на всех CRED-строках обучения PL (достижимые размеченные одно-генные пары всех 159 аннотаций пула + каузальные пары 107 позитив-только аннотаций); вероятности трёх сидов усредняются.
